# 模具：社媒组图（-s）

把长内容变成一组适合小红书等社媒分享的阅读卡，而不是将正文按长度裁切。

## 1. 先读内容，再写卡片脚本

- 识别文章题、来源、二级标题与结语。输出顺序：1 张封面 + 每章节 1 张内容卡。
- 封面回答“这组图讲什么、为什么值得读”：主标题、总领判断、主题画面、3–5 个阅读关键词。封面必须使用 `assets/social_cover_template.html`，不得套用正文卡结构。
- 封面主标题优先保持自然单行：先用最终字体、字号和标题区宽度实测；只要单行完整容纳且未挤压摘要，就不得手动插入 `<br>`、按语义停顿或为了“更像海报”强拆成两行。只有单行确实溢出、字形被压缩到影响辨识，或会侵占摘要与关键词区域时，才改为自然换行，并重新检查标题区高度。
- 封面采用明确的“文字上区 / 图片下区”结构：标题、总领判断和关键词只能出现在上区；主题画面只能出现在下区。文字不得压在图片上，也不得用图片当作文字背景。若标题或摘要过长，压缩文案或增大上区，不能侵入画面区。
- 每张内容卡只讲一个判断：标题 ≤18 字，正文通常 140–220 字，金句 ≤32 字。篇幅按卡片高度与插画占比校准：在 1080px 宽、正文 36px 的成图中，正文与金句应共同占据正文区至少 65% 的可用高度；若出现超过两段行高的无功能留白，必须补充一层“机制 / 例子 / 后果”的解释，或缩短组高后重排。保留真实人物、时间、事实与因果；删除重复铺垫。
- 金句不使用框、底色、边线、圆角、阴影或图标标记。用上下留白、略深的文字色和 `600` 字重建立层级；文字与正文左边严格对齐，正文使用常规 `400` 字重。金句是阅读节奏中的停顿，不应被做成一个独立组件。

### 正文文风：借用 ZW Book Reading 的叙事解释法

- 默认采用**沉浸式阅读视角**：让读者跟随书里的场景、行动、感受和问题向前走。正文优先写“你看见 / 走进 / 发现 / 面对什么”，让判断从场景中浮现。
- 禁止把正文写成跳出原文的第三视角解说，例如反复出现“作者先……”“本章意在……”“作者借此让读者看到……”或“这说明了……”。只有作者身份、写作动作本身确实是内容时才可简短提及。
- 面向没读过原文的人写。先用书中的一个可感场景、例子或作者动作把读者带进来，再顺着作者的推演解释判断如何成立，最后落到这件事改变了什么或留下什么问题。
- 每张正文至少包含两层：**书中具体内容**与**作者借它想让读者看到的变化**。内容足够时再补一层边界、后果或未解问题，不把正文写成概念释义或口号堆叠。
- 语气像一个认真读完的人带另一个读者走进书里：平实、具体、略带叙事。用自然推进，例如“眼前”“很快”“再往前一步”“走到这里”“于是”“最后留下”。
- 避免学术雾气、营销腔和 AI 摘要腔。少用“真正 / 核心 / 本质”，少用反复的“不是……而是……”，不用把“关键变化是”“这意味着”“它的意义在于”当作段首模板。
- 解释必须忠于原文：概括或推论可以写，但不能伪装成书中已经证明的事实；短金句若不是原文，按改写处理，不加引号或伪装成引文。

## 2. 以标题定主轴，以配文规划画面

配图的第一原则是**简洁明了**。先把标题改写成一句可以被画出来的“视觉主句”，再从配文中选择最能证明或解释这句话的 2–4 个支撑要素。图片必须让读者一眼认出卡片主题，不能只是装饰，也不能把整段配文逐项堆进一幅画。

### Image2 生图：强制门槛

- 为封面及**每一张**内容卡调用 Image2 生成一张独立插画；先完成下方的画面简表与提示词，再执行生图。生成次数必须与卡片数一致。
- 不得用 SVG、CSS 绘制、图标拼接、程序图表、占位图、图库素材或复用旧图代替 Image2 配图；即使内容适合流程图或机制图，也应让 Image2 以编辑插画方式呈现该关系。
- 将每张 Image2 生成结果保存为页码命名的独立本地资产，例如 `04-barbell-strategy.png`，在配图清单中记录「Image2 提示词 → 资产路径」的对应关系。
- Image2 不可用、无法生成或无法取得结果时，停止配图与成品交付，向用户说明阻塞原因；不得自行降级为矢量图或其他替代方案。只有用户明确要求不使用 Image2 时，才能改用其他方式。

生成前为每张卡填写以下简表：

```text
标题主轴：<标题中的主体 + 动作/关系 + 结果>
视觉主句：<只用一句话描述主画面>
配文证据：<2–4 个必须出现的对象、动作或关口>
构图类型：<单场景 / 左右对比 / 单向流程 / 阶段路径 / 决策分叉>
主体清单：<3–5 个主元素；不含背景装饰>
删除清单：<与标题无直接关系、会分散注意力的元素>
```

### 简洁性预算

- 每张图只表达 **1 个中心判断**，只使用 **1 种主要空间关系**。不要在同一张图里同时做流程、矩阵、时间线和多场景拼贴。
- 主元素控制在 **3–5 个**；流程节点通常不超过 **5 个**。超过时合并同类节点，或只画最关键的卡点与结果。
- 人物通常不超过 **3 人**，除非“群体采用”本身就是正文论点。人物必须在执行与标题有关的动作，不能只是开会、看屏幕或站立。
- 箭头只保留一条主要阅读路径；反馈闭环仅在配文确实强调“回流、复用、迭代”时使用。
- 背景只交代场景，不承载第二套叙事。删除无解释作用的电脑、抽象网络、装饰性图标和重复人物。
- 优先选择“一个强场景 + 少量关键物件”。只有标题本身是对比、流程、阶段或判断时，才使用对应图解结构。

### 标题与配文的分工

- **标题决定画什么。** 从标题中提取主体、动作/关系和结果；其中至少两项必须在主画面中直接可见。
- **配文决定怎样画清楚。** 从配文中选择 2–4 个最能解释标题的事实、动作、条件或后果，转成具体画面元素。
- **金句决定视觉重心。** 若金句是全卡结论，用尺度、位置或强调色突出对应结果；不要另加一套象征。
- 允许延伸一个与配文同方向的细节或后果，但不得改变主体意思、替换原文结论或引入未经支持的事实。

### 按图框而非通用横幅构图

- 生成前先计算实际图框比例，不能笼统要求 3:1 横幅。正文图的可用宽度为 `936px`，目标比例为 `936 / {{VISUAL_HEIGHT}}`；封面目标比例为 `1080 / ({{CARD_HEIGHT}} - 685)`。将计算结果写进配图提示，例如“按约 2.34:1 横向裁切构图”。
- 关键人物、动作和关系必须落在画面中央 76% 的安全区；左右各 12% 只允许放环境、延伸线条或可裁切的装饰。禁止把人物脸、手、关键物件或因果关系放在边缘。
- 生成后以实际卡片的图框截图检查。若 `object-fit: cover` 裁掉了关键对象，优先重新生成符合目标比例/安全区的画面；不得仅靠缩小图片或接受残缺构图。

### 图框匹配是交付门槛（不得凭感觉映射）

- **先建配图清单，后生成。** 清单至少包含：卡片文件名、标题、画面命题、`VISUAL_HEIGHT`、精确目标比例、生成提示、最终资产路径。资产命名必须使用卡片页码，例如 `06-maturity-path.png`；禁止按生成时间、文件大小或目录排序猜测图片对应关系。
- 对内容卡，提示词中的比例必须写成 `936 × {{VISUAL_HEIGHT}}` 的等效比例，并明确写出“生成画面本身接近此比例，不是把宽横幅裁进此图框”。例如 `936×560` 应写为约 `1.67:1`，`936×618` 应写为约 `1.51:1`，`936×500` 应写为约 `1.87:1`。封面也必须按 `1080 × (CARD_HEIGHT - 685)` 生成，不能复用正文比例。
- 画面命题必须能用肉眼验证地对应标题中的**关系**：比较卡要同时呈现被比较的两端与转化；流程卡要呈现顺序、关口和结果；角色卡要呈现角色、现场动作和反馈回路；边界卡要呈现选择条件。禁止以“办公室开会”“人物拿电脑”“抽象网络”等泛科技场景替代论点。
- 生成后，除整体成图外，还必须单独截取每张卡的 `figure` 图框并检查：①关键关系完整在图框内；②没有主体被边界裁掉；③即使遮住标题，读者仍能猜出该卡想解释的动作或关系。任何一项不满足，重新生成或重画，不得用 `object-position` 补救。
- 在最终交付前，随机抽检至少封面、最高图框和最低图框各一张；若卡片高度存在多种图框比例，每一种比例都至少抽检一张。

### 图文对应验收

- 建立最小映射：`标题主轴 → 主画面`，`配文证据 → 2–4 个支撑元素`，`金句结论 → 视觉重心`。主元素必须能回指到标题或配文；无法回指的元素应删除。
- 按内容选择一种构图：出现顺序用单向流程；出现对比用左右并置；出现阶段/卡点用阶段路径；出现判断条件用决策分叉；出现角色分工用动作交接。不要为了“信息丰富”混用多种构图。
- 生成提示必须包含 `Title axis`、`Visual sentence` 和 `Copy evidence`，明确唯一主题与 2–4 个支撑元素；不得只写画风与抽象意象。
- 执行“一眼测试”：缩小到手机浏览尺寸并观看 3 秒，能够说出图片在讲什么；若只能感到“科技、协作、复杂”，却说不出卡片判断，判定失败。
- 执行“遮文测试”：遮住正文，只看标题和图，仍能复述主体关系；再对照正文，至少能在图中找到两个直接对应点。无需逐句画完正文，避免因此造成拥挤。
- 执行“删减测试”：尝试删掉一个人物、节点或装饰；如果不影响标题理解，就应删除。至少抽检流程、对比、阶段/判断三类卡。

**一张内容卡必须对应一张独立生成或独立选取的插画资产。** 全组可以共用色调、纸张质感、线条语言与构图尺度，但不得把同一张图片仅靠 `object-position`、裁切、翻转、调色后重复用于多张卡。只有内容卡确实讨论同一事件的连续时间线时，才可复用同一原图的不同局部；此时必须在脚本中明确写出“连续镜头”理由，并让每个裁切呈现不同动作或信息。

```text
Use case: illustration-story
Asset type: editorial illustration for a vertical Chinese social card
Primary request: <画面命题>
Title axis: <标题中的主体、动作/关系与结果>
Visual sentence: <一句话说明唯一主画面>
Copy evidence: <来自配文的 2–4 个可见支撑元素>
Style: warm contemporary editorial collage, tactile paper grain, restrained ink linework,
one muted accent color, calm off-white background
Composition: use one clear spatial structure; 3–5 main elements; horizontal scene composed for the calculated target crop ratio; keep essential subjects inside the central 76% safe area, clean outer edges
Avoid: text, letters, numbers, logos, watermarks, neon, robot clichés, split-screen collage
```

## 3. 先测内容高度，再统一组高

- 正文为 36px、常规字重 `400`；段落间隔 32–40px，禁止用 `space-between` 把段落强行拉散。金句用 `600`，并使用比正文规则更高或相等的 CSS specificity，避免被 `.body p` 等通用段落规则覆盖。
- 先以自然内容高度渲染每张正文卡。`自然内容高度 = 顶部信息 + 标题 + 插画 + 正文/金句 + 页脚 + 上下边距`；取其中最大值，加 48–96px 阅读缓冲，并向上取整到 120px，作为全组 `{{CARD_HEIGHT}}`。不得先猜一个常见卡高。
- 将同一个 `{{CARD_HEIGHT}}` 填入封面和每张正文卡。封面和正文的版式不同。模板可用 `flex: 1` 保持页脚对齐，但只能在本节的密度验收通过时保留；不得把未测量的伸缩区当作留白。
- 每张正文卡传入 `{{VISUAL_HEIGHT}}`。默认 258px；若该卡在统一高度下比最满的一张短，优先把插画扩展至 300–480px（保持同一幅画面、改用更高裁切），再决定是否补充内容。插画只为解释判断服务，不可作为装饰性填空。
- 若插画扩展后仍不足，补一层与原文直接相关的“机制 / 例子 / 后果 / 使用提醒”；禁止为了填满版面复述结论或添加泛泛建议。

### 硬性密度验收

渲染后逐张检查并记录 `.quote` 底部与 `footer` 顶部的距离：

- 间距应为 32–96px；超过 96px 视为未完成。
- 从标题起到金句结束的内容高度，应至少占页脚以上可用高度的 80%。
- 任一卡不合格，按此顺序返工：缩短全组高度 → 增高该卡插画 → 补充一层有效内容 → 重新计算组高。不得保留大块“呼吸感”空白。
- 使用 `scripts/check_social_density.cjs <html> [html...]` 读取实际布局；脚本报错或出现 `FAIL` 时，不得交付 PNG。

## 4. 配套分享文案（内部留存）

每次生成 `-s` 社媒组图时，同步写一份可直接发布的提炼型分享文案供内部备用，但默认不作为用户交付物。

- 篇幅通常为 120–220 个汉字，分为 2–4 段；不复述每一张卡，也不把卡片标题串成目录。
- 开头从书中一个具体变化、场景或反直觉判断切入；中段收束为全组的一个总判断；结尾落到读者会如何重新看待这件事，或留下一个真实的问题。
- 保持克制、具体、可读；避免“赋能 / 颠覆 / 无缝 / 释放”等营销腔，避免空泛号召和伪金句。
- 将文案保存到 `work/<项目名>-source/分享文案.md`；不要放进最终 PNG 交付目录，也不要在最终回复中提供链接或正文，除非用户明确索要。

## 5. 模板变量与渲染

### 成品与源文件分离

- 将最终渲染 PNG 写入 `outputs/<项目名>/`；该目录只能包含成品图片。
- 将 HTML、独立配图资产、生成提示、构建脚本和检查记录写入 `work/<项目名>-source/`，供修改和复用。
- 最终回复只链接 PNG 成品目录或必要的 PNG 文件，不链接 HTML、配图资产目录和内部工作文件。

内容卡：`{{CARD_HEIGHT}}`、`{{VISUAL_HEIGHT}}`、`{{ARTICLE_SHORT}}`、`{{PAGE_INFO}}`、`{{SECTION_LABEL}}`、`{{TITLE}}`、`{{VISUAL_SRC}}`、`{{BODY_HTML}}`、`{{QUOTE}}`、`{{SOURCE_LINE}}`、`{{LOGO}}`、`{{BG_COLOR}}`、`{{ACCENT_COLOR}}`。

封面：`{{CARD_HEIGHT}}`、`{{COVER_KICKER}}`、`{{COVER_TITLE}}`、`{{COVER_SUMMARY}}`、`{{TOPICS}}`、`{{VISUAL_SRC}}`、`{{PAGE_INFO}}`、`{{SOURCE_LINE}}`、`{{LOGO}}`、`{{BG_COLOR}}`、`{{ACCENT_COLOR}}`。

将 `{{LOGO}}` 替换为本 skill `assets/avatar.png` 的 `file://` 绝对路径。用 `node assets/capture.js <html> <png> 1080 <CARD_HEIGHT>` 渲染。逐张检查标题、插画、页码、头像、姓名与来源均未裁切；核对每张 `{{VISUAL_SRC}}` 指向不同资产，并按第 3 节完成密度检查。
