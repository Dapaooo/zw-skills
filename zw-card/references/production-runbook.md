# 社媒组图生产运行手册与演进协议

用于 `zw-card -s`。目标是让不同 Agent 稳定复现同一套内容判断、配图策划、版式和验收标准；不承诺不同模型产出完全相同的措辞或 Image2 插画。

## 开始前

1. 使用完整 `zw-card/` 目录，而非只复制 `SKILL.md`；保留 `assets/`、`references/`、`scripts/`、`package.json` 和锁文件。
2. 在技能根目录安装渲染依赖：`npm ci`，然后 `npx playwright install chromium`。
3. 读取 `SKILL.md`、`references/taste.md`、`references/mode-social.md` 和本文件。
4. 取得可读的原文或用户提供材料；遇到访问墙时使用合法提供的 Markdown、PDF、截图或摘录，不绕过验证。

## 不可降级的生产契约

- 一组图是 1 张总领封面 + 每页一个独立判断，不能机械按原文段落或字数切卡。
- 面向未读过原文的读者：每页正文必须带出具体场景/事实和其后的机制、后果或边界，不能只给概念口号。
- 封面和每张正文页各有一个独立 Image2 插画。Image2 不可用时停止并报告；不得以 SVG、CSS、图标、图库、占位图或重复裁切的旧图替代。
- 成品 `outputs/<项目名>/` 只放经验证的 PNG；HTML、提示词、页码资产、构建脚本、检查输出和生产记录放 `work/<项目名>-source/`。
- 缺少任一页的资产绑定、渲染、视觉检查、尺寸检查或正文密度证据，即为部分完成，不得称为交付完成。

## 先写页码级卡片脚本

在生成、排版之前，为封面和每页正文写：

```text
页码与文件名：
标题（正文页 ≤18 字）：
独立判断：
原文依据：
正文（通常 140–220 字）：
金句（≤32 字；改写不加引号）：
Title axis（主体 + 动作/关系 + 结果）：
Visual sentence（唯一主画面）：
Copy evidence（2–4 个必须可见的事实/动作/关口）：
构图（单场景 / 左右对比 / 单向流程 / 阶段路径 / 决策分叉）：
目标图框比例、Image2 提示词、资产路径：
```

封面标题优先自然单行，只有最终字体、字号和标题区宽度实测后确实溢出或影响可读性才换行。正文从场景或行动进入，随后解释判断如何成立；避免“作者认为”“本章告诉我们”、营销腔和 AI 摘要腔。

## 图文对应与 Image2

每张图只表达一个中心判断。标题决定画什么：主体、动作/关系和结果中至少两项必须直接可见；正文提供 2–4 个画面证据。通常只保留 3–5 个主元素、至多一条主要阅读路径，不能以泛科技场景替代论点。

提示词至少写出 `Title axis`、`Visual sentence`、`Copy evidence`、精确比例和中央 76% 安全区。正文图框宽度是 `936px`，比例为 `936 / VISUAL_HEIGHT`；封面比例为 `1080 / (CARD_HEIGHT - 685)`。先按真实图框生成，再在实际 `figure` 中检查；关键关系被裁掉时重新生成，不以 `object-position` 掩盖。

按页码命名并显式绑定资产，例如 `04-decision-gate.png`。不得按生成目录、时间或文件大小猜测页面对应关系。每页至少执行：手机 3 秒测试、遮住正文后的图文对应测试、删掉一个装饰后的删减测试。

## 内容高度、渲染与验收

没有通用卡高。先按自然内容高度渲染全部正文卡，取最满页高度加 48–96px 缓冲并向上取整到 120px，得到全组 `CARD_HEIGHT`。正文页可从 `VISUAL_HEIGHT=258px` 起试；内容较短时优先把该页插画扩到合理高度（通常 300–480px），再决定是否补充与原文直接相关的机制、例子或后果。

渲染：

```bash
node assets/capture.js <html> <png> 1080 <CARD_HEIGHT>
```

正文卡验收：

```bash
node scripts/check_social_density.cjs <正文卡1.html> <正文卡2.html> ...
```

- 仅正文卡进入密度检查；封面不进入。
- 金句底部到页脚顶部间距须为 32–96px。
- 标题至金句结束的内容高度，至少占页脚以上可用高度的 80%。
- 每页检查标题、插画、页码、头像与来源未被裁切；核对每个 `VISUAL_SRC` 指向其页码资产。
- 检查最终 PNG 数量和尺寸，例如 `sips -g pixelWidth -g pixelHeight outputs/<项目名>/*.png`。尺寸正确不能替代密度 PASS。

密度失败时按此顺序修复：缩短组高 → 调整该页插画高度 → 补充有效机制/例子/后果 → 重新测量。不得靠大块空白“呼吸感”通过。

## 高频故障的处理

| 症状 | 可验证原因 | 修复 |
|---|---|---|
| 页脚前留白过大、覆盖率低 | 先猜卡高或图片高度 | 自然高度重测；调 `CARD_HEIGHT`/`VISUAL_HEIGHT`；补充具体机制 |
| 图像像泛化 AI 配图 | 标题关系未进入画面 | 重写 Title axis、Visual sentence、Copy evidence，删除无关元素 |
| 关键对象被裁 | 生成比例与实际图框不符 | 按实际比例重新生成，关键内容放中央 76% |
| 图片已生成但无交付 | 跳过映射、HTML、capture 或验收 | 补齐页码资产、渲染、检查与证据；此前只能标部分完成 |
| 生成路径或顺序不可靠 | 将生成目录当作映射 | 列出真实文件，按页码清单绑定 |
| `replaceAll` 读取 undefined | 页面缺少模板 | 构建逻辑默认 `page.template ?? card` |
| 密度负值/超过 100% | 某页图框过高 | 下调该页 `VISUAL_HEIGHT`，重渲染再检查 |
| 成品目录或链接串线 | 复用了其他项目状态 | 交付前核对标题、目录、文件数、尺寸、检查输出与最终 PNG |

## 每次使用都留下可维护的学习

每次任务都在 `work/<项目名>-source/生产记录.md` 留下以下条目：状态；页面和页码资产映射；`CARD_HEIGHT` 与逐页 `VISUAL_HEIGHT`；PNG 尺寸与密度输出；图框/3 秒/遮文/删减检查；一条可复核的观察；原因与处理；一条候选经验或“无”。

只有满足下列条件的候选经验才进入本文件：有本次真实证据；明确触发条件、症状和处理；不含用户私有内容、凭据、链接或临时目录；不将单次偶然的尺寸、画风或模型结果泛化为固定规则。任务未产生新经验时，仍写生产记录，但不为了“进化”杜撰规则。

若技能目录属于用户授权可维护的 Git 工作区，完成后把合格经验写回本文件并提交；否则保留生产记录供下一次任务读取，并明确说明全局规则尚未保存。
