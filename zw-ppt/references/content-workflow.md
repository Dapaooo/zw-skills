# Content and narrative workflow

## 1. Define the communication problem

Write a one-sentence brief before outlining:

> Help [audience] understand/believe/decide [outcome] within [time and context], using [evidence and tone].

Separate three kinds of presentation use:

- **Live**: fewer words, stronger sequence, speaker carries nuance.
- **Self-reading**: more explicit reasoning, sources, labels, and navigation.
- **Hybrid**: concise main message plus enough evidence to remain understandable without narration.

## 2. Choose an appropriate narrative pattern

Select and adapt; do not apply mechanically.

### Decision or proposal

Context → evidence → tension or opportunity → alternatives → recommendation → plan → decision.

### Strategy

Current position → structural change → implications → choices → strategic logic → capability roadmap.

### Research or report

Question → method and evidence → findings → interpretation → limits → implications.

### Training

Why it matters → mental model → mechanism → demonstration → guided practice → application → recap.

### Product or launch

User situation → unmet need → product idea → experience → proof → adoption path.

### Keynote or story

Hook → shared reality → tension → new lens → memorable examples → invitation or call to action.

### Progress or review

Goal → work completed → evidence → variance → lessons → next commitments → asks.

## 3. Create a page map

Use a table like this before production:

| # | Slide job | Message title | Evidence/content | Visual form | Notes | Source status |
|---|---|---|---|---|---|---|
| 1 | Establish stakes | Direct message | One key fact | Hero image | Opening | Verified |
| 2 | Orient audience | Direct message | Three-part map | Diagram | Transition | Synthesis |

The “slide job” should be a verb: establish, compare, explain, prove, diagnose, transition, decide, or commit.

## 4. Write message titles

Prefer titles that remain useful when read alone in the overview.

Weak:

- 市场分析
- 我们的方案
- 三个问题
- 未来展望

Stronger:

- 客户选择正在从单项价格转向全生命周期价值
- 三个经营漏点决定项目利润能否兑现
- 第一阶段用真实业务验证可复制性
- 未来增长来自持续服务与新产品的接力

Avoid:

- long academic sentences;
- empty superlatives;
- excessive quotation marks;
- habitual “不是……而是……” framing;
- titles that merely name a topic without stating a point.

### Keep visible language inside the content

Visible slide copy should state the subject, question, relationship, or decision. It should not comment on the existence or sequence of the presentation.

Prefer:

- `先回答三个问题`
- `从单点业务闭环到系统协同`
- `怎样进入制造业务`

Avoid visible phrases such as:

- `整场演示围绕……展开`
- `接下来我们先看……再看……`
- `这一页说明……`
- `后面将会介绍……`

Move necessary speaking directions and transition commentary into speaker notes.

## 5. Control density

Use one dominant message per slide. Keep supporting content subordinate.

- If two conclusions need equal visual weight, split the slide.
- If the audience must compare repeated fields, use a table, matrix, or aligned cards.
- If the content describes change over time, use a timeline or curve.
- If one element affects several others, use a system map or flow.
- If the slide only lists items, ask what relationship the audience needs to see.

Do not shrink text to rescue an overloaded slide. Cut, group, or move detail to notes/appendix.

## 6. Use chapter transitions deliberately

A transition page should contain:

- a readable section marker;
- the next chapter's central question or promise;
- a short route through the next pages;
- a visual that changes pace.

Do not use a transition after every few pages. Use it when the reasoning changes mode.

Treat the chapter name as the primary title. Treat the chapter promise or explanation as secondary copy. Do not make a generic explanatory slogan visually larger than the chapter title.

Before building repeated case pages, define the classification labels once and apply them consistently across the group. A label should describe the reasoning role of the case, such as `中小企业小闭环` or `大型企业系统协同`, rather than fall back to a generic `真实企业案例`.

## 7. Handle evidence honestly

- Put exact facts and citations on the slide when they drive the decision.
- Put methodological detail in notes or appendix when it interrupts the live flow.
- Label illustrative numbers, scenarios, and strategic curves as non-forecast when they are not validated forecasts.
- Distinguish external diagnosis from confirmed internal problems.
- Do not invent founder stories, market rank, financial scale, customer results, or technical capability.

## 8. Write speaker notes

Use notes to add what should be spoken but not displayed:

- opening sentence and transition;
- interpretation of evidence;
- caveat or source boundary;
- likely audience question;
- decision or next-step prompt.

Do not duplicate the slide word for word.
