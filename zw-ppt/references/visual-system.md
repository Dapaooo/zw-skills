# Visual system

## 1. Start with art direction

Define the deck in one visual sentence, for example:

> Calm editorial report with warm documentary images, strong typographic hierarchy, and restrained diagrams.

Derive the system from the material, not from a favorite style. Decide:

- emotional register;
- presentation environment;
- light/dark balance;
- type personality;
- image realism or abstraction;
- diagram geometry;
- density and whitespace;
- degree of motion.

## 2. Build hierarchy for a room

For 16:9 slides, use these as practical starting points, then verify by rendering:

- title: roughly 42–72 px/pt equivalent;
- section marker or eyebrow: 18–26;
- body: 24–34;
- source or legal line: 15–20, only when necessary;
- chart labels: at least 18–22 for live projection.

Do not use tiny body text to preserve every paragraph. A speaker can explain; a self-reading appendix can hold detail.

For chapter transitions, make the actual chapter title the dominant text. Use the explanatory statement as a smaller secondary headline, followed by at most one short supporting paragraph. Verify this hierarchy at contact-sheet size as well as full-slide size.

## 3. Use the whole canvas

Avoid content clustering in the upper-left with unused lower space.

Balance the canvas through:

- split layouts;
- full-bleed or half-bleed images;
- anchored diagrams;
- aligned comparison fields;
- bottom summary bands;
- deliberate asymmetry;
- focal whitespace rather than accidental emptiness.

Keep recurring margins and alignment lines consistent, while varying page structure enough to create rhythm.

## 4. Choose a visual form for the relationship

- **Sequence**: timeline, stepped path, process rail.
- **Comparison**: table, aligned cards, before/after, matrix.
- **Hierarchy**: stack, pyramid, nested layers, tree.
- **System**: flow, hub-and-spoke, causal loop, architecture map.
- **Change over time**: line, area, slope, staged curve.
- **Portfolio**: family lineup, spectrum, 2×2, tiered offering.
- **Evidence**: annotated image, large number, source-backed callout.

If a diagram needs a paragraph to explain where the lines go, redesign it.

Prefer operational flows over abstract layers when the audience must understand how work happens. Name the actors, inputs, outputs, handoffs, responsibility, and changed result. A useful test is whether the presenter can trace the diagram with one finger and explain it in one sentence.

## 5. Use cards selectively

Cards are useful for repeated fields and comparisons. They are not the default container for every sentence.

Avoid:

- endless grids of identical rounded rectangles;
- decorative icons with no semantic value;
- multiple nested cards;
- small text inside large empty cards;
- six or more equal-weight elements when prioritization is needed.

## 6. Work with images

Use real supplied images when authenticity matters. Use generated imagery for scenes that cannot be sourced, conceptual backgrounds, controlled compositions, or coherent cutouts.

For generated images:

- specify intended slide role and aspect ratio;
- reserve negative space where text will sit;
- match lighting, perspective, and palette to the deck;
- avoid embedded text unless the image itself requires it;
- generate page-specific scenes instead of reusing one image repeatedly;
- avoid generic neon AI brains, floating holograms, and anonymous corporate handshakes unless the topic truly requires them.

Integrate images into the composition using masks, gradients, cropping, foreground overlap, and annotation. Do not simply place a stock rectangle beside text on every page.

For high-fidelity HTML-first work, treat the image and page layout as one design problem. Plan the text zone before generating the scene, then use the image's negative space, subject direction, lighting, and crop to guide the composition. A technically relevant image that does not cooperate with the page layout should be regenerated or rejected.

## 7. Design charts honestly

- Use a quantitative chart only when data supports it.
- Label strategic or illustrative curves as such.
- Keep axes, units, time periods, and sources explicit.
- Highlight the intended reading and mute secondary elements.
- Align points, connectors, and labels precisely.
- Avoid 3D effects and decorative chart junk.

## 8. Use color as a system

Define roles, not just hex values:

- canvas;
- primary ink;
- muted ink;
- accent;
- secondary accent;
- positive/negative/warning;
- border and surface.

Use dark slides only when they create meaningful emphasis or support the chosen art direction. A fully light or fully dark deck is acceptable if the context supports it.

## 9. Motion and interaction

Motion should reveal sequence, explain change, or support live pacing.

- Keep content visible by default.
- Never depend on animation JavaScript to make core content appear.
- Ensure PDF/static export remains complete.
- Respect reduced-motion settings in HTML.

## 10. Remove generic AI visual habits

Before delivery, look for and remove:

- repeated hero images;
- unexplained glassmorphism;
- arbitrary gradients;
- excessive pills and badges;
- too many small icons;
- identical page compositions;
- overuse of “01/02/03” when hierarchy is already clear;
- visual metaphors that do not match the content.
