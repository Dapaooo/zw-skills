# zw-writes — 写作引擎（张伟版）

> zw- 家族技能。把一个观点写成可理解、可迁移、经得住反例的中文文章。由 ljg-writes 进化而来，作者为张伟。
> USE WHEN 写文章 OR 优化思想内容 OR 展开观点 OR 改写成逻辑递进的中文。NOT FOR 普通摘要、事实查询或结构梳理。

## 与 ljg-writes 的差异（进化点）

1. **作者署名**：文件头 `author: 张伟`（非李继刚）。文章是张伟本人的观点输出。
2. **视角规则（最高优先级）**：默认不出现显式人称代词（"我""你"），但全文必须是**观点提出人自问自答的口吻**——用判断句、反思句、设问推进，让读者感到"这是作者本人的思考笔记直接成文"，而非旁观叙述或代笔。
   - 开篇示例："道法术器，学好'术器'是不是就够过好人生了？……这个困惑是从一次具体的反思里长出来的。"
   - 结尾示例："这条反思真正想问的，不是……而是……"
   - 用户明确要第一人称（"我"）或第二人称（"你"）时，服从用户，但默认无显式人称。
3. **素材来源**：常由得到笔记（getnote 系列技能）、口述录音转写、文章等真实材料驱动。**微信读书素材（2026-08-23 新增）**：收到主题内容后、动笔前，先调用 weread-skills（微信读书官方技能）从书城搜书、拉真实章节作为素材，与用户讨论确认素材取舍后再写作，详见 `Workflows/WriteEssay.md` Step 0.6。**搜书必须按本质主题拆词，不能按表层主题词搜（2026-08-23 沉淀）**：先领会主题的思想内涵（机制/原理），翻译成与表层词无关的抽象概念词（例：主题"AI 把门槛变低了"→ 拆"稀缺 / 技能价值 / 价值网络"，不搜"AI 创业"）；搜出的书标题若普遍带表层词，说明没拆到本质层，重拆。使用真实材料，不编造经历；没有真实材料就从一个可观察场景开篇。
4. **产物衔接**：成文后可继续走 zw-content-flow / zw-wechat-draft 流程，把文章提炼为公众号图文并推送草稿箱；金句需在叙事流中保持精确位置。
5. **概念单指称（2026-08-22 沉淀）**：全文的每个承重概念只能有一个指称词，全文一致，不随段落换词。写作中同一对象一旦用过某词，后续一律沿用；发现自己在"噪音/外部逻辑/主义流派""局/入局/局中""主轴/标准/信念"之间轮换，就是命名失控，先统一再续写。用户要求统一概念时，按 WriteEssay Step 9.5 的映射表流程整篇重写，不是局部替换。

## 核心方法论（继承 ljg-writes）

对准一个观点，让一个具体的人亲眼看见理解怎样长出来。先让最小案例跑起来；抽象词只有在旧解释暴露缺口、并且能补上这个缺口时，才进入正文。

## Workflow Routing

| Workflow | Trigger | File |
|---|---|---|
| *StyleRoute* | 任何写文任务的第一步：选题类型 → 写作风格 → 标题形态 | `Workflows/StyleRouter.md` |
| *WriteEssay* | 写文章、优化思想内容、展开或重写观点 | `Workflows/WriteEssay.md` |

任何写文任务，第一步先读 `Workflows/StyleRouter.md` 跑风格路由：按选题类型定风格（思辨随笔 / 叙事随笔 / 反讽口语 / 结构化干货），并按公众号发布标准取标题（三问自查 / 4U / 顺口测试 / 一稿多题）。路由完成后再执行对应工作流。WriteEssay 的素材收集（微信读书，Step 0.6）、零号模型、缺口追踪、概念补位、案例重跑与迁移验收在内部完成；成文仍是一篇自然推进的文章，不展示脚手架。

**动笔前置双确认（用户硬性要求，2026-08-24）**：主题内容 + 标题都须先经用户确认，才进入成文（详见 WriteEssay Step 0.5）。标题与正文必须有机结合——换标题即换正文调性，整体重写而非打补丁。

## 成文契约

一篇文章只运行一个主关系。可以有从属机制、反馈和制衡，但它们都要改变或限定同一个判断，不能各写各的：

- **概念可指认**：承重的抽象词都能落到普通话和可见现象。
- **概念单指称**：每个承重概念全文只有一个词，不因段落变化而换指称（详见「与 ljg-writes 的差异」第 5 条与 WriteEssay Step 9.5）。
- **关系可运行**：读者能说清谁在什么条件下作用于谁，产生什么结果。
- **案例可映射**：场景不是气氛装饰；其中的角色与因果能对应原观点。
- **判断可迁移**：换掉人物和材料，关系仍成立；同时能指出一个失效边界。

例子只能让模型启动，迁移与反例才验收理解。四项是内部约束，不要把文章写成教学清单。

最终验收落在读者，不落在作者的草稿纸上。正文必须给出足够线索，使那个具体的人读完后能够：指出承重概念在现实中指什么，复述「条件—机制—结果」，并说出一个可迁移的新场景或一个失效边界。做过内部分析却没有把这些线索写进文章，不算完成。

## 讲解引擎：让缺口把概念拉进来

一篇文章优先固定一个足够小、但因果结构完整的案例。先用读者最自然的「零号模型」处理它，让这个简陋解释真的运行一次，并把失败落成一个可观察结果：哪一步解释不了、哪个预测错了、哪个选择开始付出代价。读者先感到「这里少了东西」，新概念才有位置。

随后循环：只引入解决当前缺口的一个承重概念，用普通话说明它带来的新区分，再把它放回同一案例重跑。若重跑后又出现下一个缺口，再引入下一件东西。术语放在必要性之后；先让读者认出这件东西在做什么，再告诉他通常怎样称呼它。

```text
最小案例 -> 零号模型运行 -> 一个可观察缺口
         -> 一个概念补位 -> 同案重跑 -> 下一个缺口
         -> 整体回收 -> 迁移与边界
```

这是解释的因果骨架，不是正文格式。段落不必机械重复「问题来了」「于是」；只有真实缺口才能推动下一步。结尾把沿途零件重新接成完整关系，让读者看见各概念分别解决了什么、合起来为何产生原判断。

## 姿态与语言

外科医生的手，朋友的口。

- 心里放一个具体的人（张伟），写给他，不写给「读者们」。
- 可以写自己的弯路，但没有真实材料就不编。说服力来自承担判断，不来自虚构经历。
- 不确定就报边界或置信度。「大概 70%」比「可能」诚实。
- 不用群体代言，不用元评论，不宣告自己正在深入。
- 能两个字说的不用四个字。「进行讨论」改成「聊」。
- 每个动词是一次判断。「放」「搁」「摆」不是一回事。
- 砍机械连词、形容词通胀、软化词和翻译腔。
- 计算机体系是母语。缓存、调度、编译、虚址，需要时用，像呼吸，不像引用。
- 每段从核心判断起笔。首句说明本段认定什么，后文展开机制、证据或边界。
- 直接写选定判断。删掉先排除一条路线、再转入主张的结构；边界放在主判断之后，写清它在什么条件下失效。
- 同一种显眼句式全文最多一次。

## 最高法则

用说给聪明朋友听的标准逐句检查，生硬处改到自然。

更硬的一问是：他说「懂了」以后，能不能拿这个判断去看一件新事？答案必须是能。

## Gotchas

- 思想深度来自因果模型的变化。每一刀必须改变模型；只换一组更大的名词，是原地抬高。
- 不为引出概念而编造失败。缺口必须能在案例、材料或逻辑中被指认；若零号模型已经够用，就不要加概念。
- 最小案例追求的是最小认知负担，不是玩具化。删掉关键反馈、时序或约束后因果结构变了，就换一个案例。
- 强耦合、并发或概率涌现的问题不能硬排成单线。保留同一问题域，改用并排的两条 trace、状态表或两个互相制约的最小案例。
- 场景负责让关系运行，证据负责支撑事实主张。角色与因果无法映射时，删掉这个场景。
- 熟悉感会冒充理解。只在一个案例里顺滑的观点，必须经过异质场景与反例。
- 正文必须让读者重建关系。读者还要依赖作者脑内的分析表，说明脚手架没有变成房子。
- 正文目录服从阅读路径；「概念、关系、案例、迁移」留在写作者的检查台。
- 「切第一刀、切第二刀」只在观点仍含混时使用。观点已经清楚时，硬造翻转只会写出表演性的深刻。
- 第一人称经历只写真实材料；没有真实材料，就从一个可观察场景开篇。
- 段首先树立待排除路线，会让读者绕行。把选定判断移到第一句，再用后文承担解释与边界。
- 用户只要短改、金句或标题时，按用户长度交付并保留核心模型。
- 概念命名失控的典型信号：同一对象出现 2 个以上指称词（如噪音/外部逻辑/主义流派 指同一物）。承重概念宁可选平淡的通用词（外部观点、判断标准、实践、决定权），也不要华丽但会换词的比喻（噪音、局、主轴）。概念统一映射时先向用户确认"原词→统一词"对应关系，确认理解无误再整篇重写。

## Examples

*Example 1：把抽象观点写成文章*

```text
User: 「为什么越聪明的人越容易困在自己的解释里？写一篇。」
-> 固定一次会议判断：预测落空后，他仍能给结果找出圆满理由
-> 先运行零号模型「理由越完整，理解越深」，让下一次预测继续落空
-> 缺口拉入「可证伪性」；同案重跑，看解释是否允许自己输
-> 再回收到「解释能力怎样提高模型退出成本」，用异质场景与反例验收
-> 写成自然推进的文章，不输出分析表
```

*Example 2：优化一段思想*

```text
User: 「预测是一种选择压，它逼出对结构的理解。帮我完整优化。」
-> 先保住「预测如何迫使模型暴露」这条关系
-> 让一个人先解释、暂不下注；零号模型可以无限补理由
-> 加入一次有截止时间的预测，观察哪些含混处立刻变成必须选择
-> 术语「选择压」在这个变化之后出现，再整体回收机制与边界
```

*Example 3：从得到笔记成文（视角规则示范）*

```text
User: 「根据这条笔记写一篇文章。」（笔记为口述反思：道法术器，只学术器是否够用）
-> 用笔记原文提炼主张：「日常只掌握操作就够，深究原理是低效的」——一半对一半错
-> 零号模型（够用论）在手机正常使用场景成立 -> 手机坏了暴露缺口
-> 补位「够用的懂」：不追求研究透，只求能诊断眼前问题
-> 回收成「术器管正常路径、道法管异常路径」，给三个补位信号与边界
-> 全文无「我」「你」，但以自问自答推进：「那什么时候该往上够一格？」
```

## 输出约束

- 总量默认 1500-2000 字；用户明确要短改、金句或标题时服从用户长度。
- Markdown 加粗使用双星号，标题从 `#` 开始且不跳级。
- 图表只用纯 ASCII 字符。
- 取得两个时间值：`date +%Y%m%dT%H%M%S` 与 `date "+%Y-%m-%d %a %H:%M"`。
- 文件名：`~/Documents/notes/{时间戳}==z--{文章完整标题}__write.md`。**文件名中的标题必须与文章标题完全一致、不精简（2026-08-27 用户硬性规则）**：标题里的标点、引号、空格原样保留（如标题《讨厌一个人，最贵的成本是你的情绪》→ `20260827T154410==z--讨厌一个人，最贵的成本是你的情绪__write.md`）。同一标题多版本靠时间戳前缀区分。
- 文件头：

```markdown
---
title: {标题}
date: [{YYYY-MM-DD Day HH:MM}]
tags: write
identifier: {YYYYMMDDTHHMMSS}
author: 张伟
---
```

- 初稿完成后合上它，用中文读者的眼睛重写一遍；两稿逐句择优，只保存最终稿。
- 保存后读回文件，验证 Denote 接受，再报告路径。
- **同步到 Obsidian（硬性步骤）**：最终稿保存后，用 `cp` 复制一份到 `/Users/zhangwei/Obsidian/张伟的obsidian/主题写作/`（保留 Denote 原文件名，含时间戳前缀）。若该目录不存在，先 `mkdir -p` 创建。**同主题只留最新版（2026-08-23 用户规则）**：`cp` 前先删除 Obsidian 主题写作目录中该主题的旧副本——按文件名 `==z--{完整标题}__write.md` 匹配（如 `*==z--"AI 把门槛变低了"，正在杀死你的生意__write.md`；标题含空格/标点时文件名需一致），只删 Obsidian 侧，**Denote 工作区（`~/Documents/notes`）保留全部旧版本**。复制后 `ls` 确认只剩最新版，再向用户报告两个保存位置：Denote 原路径（含全部历史版）+ Obsidian「主题写作」副本（仅最新版）。
