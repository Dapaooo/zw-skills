# zw-wenfeng-review — 文风与内容编排审核

> zw- 家族技能：把 zw-card / zw-wechat-draft 沉淀的「提炼 + 品味 + 文风」规则固化为一份可执行的审核清单，用于把关所有文字内容产出。审核对象可以是公众号图文、长图文案、卡片文字、访谈提炼、报告摘要、任意正文段落。

## 触发场景

- 用户说「审核这篇/这段文字」「看看文风有没有问题」「AI 味重不重」「有没有翻译腔」
- 用户在发布（推公众号、铸卡片、发小红书）之前要求先把关文字
- 用户给出任意一段文字产出，要求按既定的文风标准检查

## 审核原则（先审后改）

本技能**只做审核与建议**，不擅自改写全文。流程：

1. 通读待审内容，理解其类型（叙事 / 访谈提炼 / 摘要 / 评论 / 报告段落等）
2. 按下方三组规则逐项检查，标注**问题位置 + 原文摘录 + 问题类型 + 修改建议**
3. 输出审核报告：逐项问题清单 + 总体结论（通过 / 需修改 / 重写）
4. 若用户要求，再基于报告做改写；改写后复检一遍

## 审核维度一：内容编排（提炼度）

适用于「对原文做提炼/摘要」类的产出（公众号图文、阅读卡、访谈摘要等）。核心判据：**产出是不是「有人帮你读完并划了重点」，而不是复制全文。**

### 1.1 提炼度自检
- 目标篇幅：长文/访谈提炼后约为原文 **1/3 ~ 1/2**
- 若产出几乎与原文等长 → **未提炼，需重做**
- 砍掉寒暄、重复、冗余问答铺陈；保留核心论点、章节脉络、关键引述

### 1.2 金句识别与位置
- 金句判据：**独立成段、< 25 字、承载核心洞察**的短句
- 金句/引用必须保留在**原文叙事流中的精确位置**——出现在哪段之后，就紧跟在那段之后；**严禁把同一章节的金句全部堆到章节末尾**（最常见的错位）
- 原文中已被作者加粗或作为引述的高价值句，优先保留

### 1.3 层级判断
- 一级内容章节 → 标题级别 1（如 `##`）
- 章节内编号子标题 / 独立小节 → 标题级别 2（如 `###`）——**这是内容标题，必须用更深的标题层级**
- 装饰性标签（来源信息、分类标签、日期）→ 眉题/副标题样式，**绝不用于内容标题**

### 1.4 来源标注
- 内容取自第三方（文章/报告/访谈/书籍）→ 必须显式标注来源：**媒体/公众号/作者名 + 发布日期**
- 存疑时以原文标注为准，**不臆造出处、不遗漏出处**
- 格式惯例：副标题处标注「来源 · 日期」（如 `易论AI 深度对话 · 2026.07.09`）；卡片页脚标注《出处》· 作者（如 `《财经》· 吴俊宇 周源`）

## 审核维度二：文风（反 AI 腔 + 反翻译腔）

### 2.1 反 AI 文案腔（命中即标红）
- **禁空洞动词**：「赋能」「无缝」「释放」「下一代」「打通」「闭环」→ 建议换成具体动词
- **禁通用人名**：John Doe、Sarah Chan、Jack Su 之类占位人名
- **禁假数据**：`99.99%`、`50%`、`1234567` 这类过于「干净」的数字 → 用有真实感的「脏」数据（如 `47.2%`）
- **禁模板化品牌名**：Acme、Nexus、SmartFlow 之类烂大街名字

### 2.2 反翻译腔（命中即重写，规则详见 `references/style-rules.md`）
- 名词化的抽象（「共相被肢解」「普遍现象」）
- 英式对仗（「两个尺度，一个舞台」「输入连续，输出不连续」）
- 工业短句堆砌（纯短句排比，节奏无起伏）
- 形容词驱动（「突然的、惊人的、深刻的、根本的」）
- 被动滥用（「被推到死」「被发现」）
- 「是…的」句式（「这是值得思考的」→「值得想想」）
- 长定语后置（「在…的背景下」「基于…的考虑」「对于…而言」）
- 抽象主语（「该方法」「这种思路」「上述论点」→ 换成具体的「它」或省略）
- 「进行 + 名词」结构（「进行讨论」→「聊」、「进行优化」→「调」）
- 学术腔模板（「随着 X 的发展」「通过对 Z 的分析」）
- 长复合句：**超过 3 个逗号的句子，建议砍成短句**

**该用的写法**：动词驱动（「球稳坐」「谷塌了」）、具体物件（「水」「球」「谷」而非「状态」「系统」）、口语节奏（「它就这么…跳了」）、中文自然句式——长句不怕长，短句不怕短，怕的是机械对仗。

**逐句检查法**：每句默念出声。听起来像翻译的、像维基百科中文版的、像论文摘要的——重写。重写不动的，拆成 2-3 个短句。整段回看节奏：句长是否有变化？纯短句堆砌同样是翻译腔。

### 2.3 数字与术语
- 必要专有名词、人名、产品名、精确数字可保留原文（如 Fei-Fei Li、ImageNet、Transformer、47.2%）
- 除上述之外，英文长句一律翻译成中文，不做中英混杂

## 审核维度三：叙事结构（适用于叙事/讲解类内容）

用于视觉笔记、讲解类、概念解读类内容。六条公理缺一不可（详见 `references/style-rules.md`）：

1. **有真问题在前**：从具体的、可触摸的、卡住的问题开始，不是教科书式「什么是 X」
2. **必须有失败**：路径中至少包含一次失败/走偏/半对——线性推导会杀掉张力
3. **顿悟在前、命名在后**：先让读者「看到」，再告诉名字；**标题不能出现概念名**（「打不开的盒子」可以，「黑箱理论」不可以）
4. **「现在」视角，非「上帝」视角**：时间锚点是「那一刻能看到什么」，不是 100 年后回望
5. **文字克制，不点题**：禁止「你重新发明了它」「你见证了它的诞生」这类元自指话术——发明感来自叙事张力，告诉就破
6. **中文母语表达**：见维度二之反翻译腔

## 审核报告格式

按以下结构输出，逐项列出：

```
【内容编排】提炼度 / 金句位置 / 层级 / 来源标注 —— 每项：通过 或 问题
【文风】AI 腔 / 翻译腔 / 数字术语 —— 每项：问题句摘录 + 问题类型 + 改写建议
【叙事结构】（如适用）—— 六公理逐条判定
【总体结论】通过 / 需修改 / 重写 + 一句话理由
```

问题摘录必须引用原文，修改建议必须给出可直接替换的具体句子（对照示例见 `references/style-rules.md`）。
