## 一、反 AI 文案腔清单

命中即标红，替换为具体表达：

| 禁忌 | 示例 | 建议 |
|------|------|------|
| 空洞大词 | 赋能、无缝、释放、下一代、打通、闭环、抓手、颗粒度 | 用具体动词描述实际动作 |
| 通用占位人名 | John Doe、Sarah Chan、Jack Su | 用有创意的真实名字，或直接用「某人」 |
| 假数据 | 99.99%、50%、1234567 | 用有真实感的「脏」数据：47.2%、+1 (312) 847-1928 |
| 模板化品牌名 | Acme、Nexus、SmartFlow | 发明有品味的名字，或直接用真实名 |

自检问题：
- [ ] 有没有「赋能/无缝/释放/下一代」这类词？换成具体动词。
- [ ] 数字是不是太「干净」了（全是 99.99%、50%）？有没有真实感？
- [ ] 有没有占位人名或烂大街的虚构品牌名？

## 二、反翻译腔清单（命中即重写）

**核心判据：文字必须像中文人说话，不像英文翻译过来的中文。**

### 禁忌项（逐条排查）

1. **名词化的抽象**：把动词变成名词再套上修饰
   - ✗「共相被肢解」「现象学碎片化」「普遍现象」
   - ✓ 换成具体说法：「各管各的，谁也不挨谁」
2. **英式对仗**：两个结构完全平行、字数对称的句子
   - ✗「两个尺度，一个舞台」「输入连续，输出不连续」
   - ✓「慢慢加热，到 100 度突然就开了」
3. **工业短句堆砌**：全是短句，节奏机械
   - ✗「球瞬间到位。地形慢慢变。两个尺度，一个舞台。」
   - ✓ 长短句交替，有起伏
4. **形容词驱动**：靠形容词堆情绪
   - ✗「突然的、惊人的、深刻的、根本的」
5. **被动滥用**
   - ✗「被推到死」「被肢解」「被发现」
   - ✓ 用主动句
6. **「是…的」句式**
   - ✗「这是值得思考的」「这是值得深入探讨的」
   - ✓「值得想想」「这事得琢磨」
7. **长定语后置（介词框架）**
   - ✗「在…的背景下」「基于…的考虑」「对于…而言」
   - ✓ 全部删掉，直接说
8. **抽象主语**
   - ✗「该方法」「这种思路」「上述论点」
   - ✓ 换成具体的「它」，或直接省略
9. **「进行 + 名词」结构**
   - ✗「进行讨论」「进行优化」「进行处理」
   - ✓「聊」「调」「处理」
10. **学术腔模板**
    - ✗「随着 X 的发展」「在 Y 的过程中」「通过对 Z 的分析」
11. **长复合句**
    - **超过 3 个逗号的句子，砍成短句**
    - ✗「该方法在多个维度上都展现出了一定的优势，且在不同场景下的表现存在明显差异，需要结合具体情况进一步分析，以确定其适用性。」
    - ✓ 拆成 2-3 句

### 该用的写法

- ✓ **动词驱动**：「球稳坐」「谷塌了」「它跳了」「推到塌」
- ✓ **具体物件**：「水」「球」「谷」，而不是「状态」「系统」「势函数」——除非确有必要
- ✓ **口语节奏**：「它就这么……跳了」「看着是这样，其实不是」
- ✓ **中文自然句式**：长句不怕长，短句不怕短，怕的是机械对仗

### 对照示例（改稿标准）

| ✗ 翻译腔 | ✓ 中文母语 |
|----------|-----------|
| 输入连续，输出不连续 | 慢慢加热，到 100 度突然就开了 |
| 共相被肢解 | 各管各的，谁也不挨谁 |
| 状态稳坐在谷里。谷在变。当谷消失，跳变发生。 | 球稳稳待在谷里。谷慢慢变。谷一塌，球就跳。 |
| 该方法在多个维度上都展现了一定优势 | 它在好几处都比老办法强 |
| 在 AI 工程实践中，并行处理是否合适？ | 并行海投错在哪？ |
| 这是一个值得我们深入思考的问题 | 这事得想想 |

### 逐句检查方法

1. 把整篇文字扫一遍，逐句默念出声
2. 听起来像翻译的、像维基百科中文版的、像论文摘要的 → 重写
3. 重写不动的，把那一句拆成 2-3 个短句
4. 整段读完后回看：节奏是否有起伏？句长是否有变化？**纯短句堆砌也是翻译腔（工业短句堆砌）**
5. 任何一处英文术语不可避免（人名、产品名）——接受，但前后中文必须 native

## 三、数字与术语规则

- 保留原文：人名、机构名、公司名、产品名、项目/论文名、专业术语（如 Fei-Fei Li、ImageNet、Transformer）、精确数字/单位
- 除此之外，英文长句一律翻译成中文；不做中英混杂，不用引号标注大段英文原文
- 摘要/总结类内容除必要专有名词外，一律用简体中文

## 四、叙事六公理（适用于叙事/讲解/概念解读类）

### 公理 1 · 有真问题在前

每篇必须以一个**具体的、可触摸的、卡住的问题**开始。
- ✗ 教科书式：「什么是 X」
- ✓ 困境式：「当时的人们用 A、B、C 都不够，因为……」
- 问题必须有裂缝，裂缝必须可感——读者自己能感到「嗯，这确实卡住了」
- 削掉它：失去叙事的发动机，退化为时间线

### 公理 2 · 必须有失败

路径中必须包含**至少一次失败**（或走偏、半对了）。线性推导（「由此可得」）会杀掉张力。
- 失败让读者明白：不是只有这一条路，是别的路都走不通
- 削掉它：变成定理证明，读者点头但没占有

### 公理 3 · 顿悟在前、命名在后

读者必须先「看到那个东西」（顿悟时刻），再被告诉「这个东西叫……」。
- 先抛概念名再解释 = 剧透。**命名必须是路径的终点，不是起点**
- 标题不能出现概念名：「打不开的盒子」可以，「黑箱理论」不可以

### 公理 4 · 「现在」视角，非「上帝」视角

每一站，时间锚点是「他/她在那一刻能看到什么」，不是「我们站在 100 年后回望」。
- 后世评价、连锁影响、与其他概念的对比——都是路径外的事，不进画面

### 公理 5 · 文字克制，不点题

让叙事张力自己产生发明感，不靠元自指话术。
- ✗「你以为你刚才学到了一个概念。其实你刚才不得不发明了它。」
- ✗「你重新分娩了它」「你亲身发明了它」「你见证了它的诞生」
- ✓ 允许的余韵（诗意而非元论）：「于是，你看见了山。」「门一旦开过一次，就不会再合上。」
- 读者的发明感来自叙事张力（失败可见/转折顿挫/视觉惊讶），不来自被告知「你正在发明」。**告诉就破**

### 公理 6 · 中文母语表达

见本文件「二、反翻译腔清单」。

## 五、内容编排规则（提炼类产出）

适用于把长文/访谈/报告提炼为摘要、公众号图文、阅读卡的场景。

### 提炼度
- 目标篇幅：原文的 **1/3 ~ 1/2**
- 读起来应像「有人帮你读完并划了重点」，而非复制粘贴全文
- 若产出几乎与原文等长 = 未提炼，需重做

### 金句识别
- 判据：独立成段、**< 25 字**、承载核心洞察的短句
- 与普通加粗的区别：金句用强调样式（如左边线），普通加粗保留原文中已被作者加粗的高价值句

### 金句位置（关键，最常见的错位）
- 金句/引用必须保留在**原文叙事流中的精确位置**——它出现在哪一段之后，就紧跟在那一段之后渲染
- **严禁把同一章节内的金句/引用全部堆到章节正文末尾**
- 实现方式：章节标题与正文分离，正文拆段，金句按叙事顺序穿插在段落之间

### 层级判断
- 一级内容章节 → 最高标题级别
- 章节内编号子标题/独立小节 → 次一级标题级别（**这是内容标题，必须用标题层级，不可用装饰样式**）
- 装饰性标签（来源、分类、日期）→ 眉题样式，**绝不用于内容标题**

### 来源标注（必做）
- 内容取自第三方 → 必须显式标注来源：**媒体/公众号/作者名 + 发布日期**
- 格式惯例：
  - 封面/正文开头：`来源 · 日期`（如 `易论AI 深度对话 · 2026.07.09`）
  - 卡片页脚：`《出处》· 作者`（如 `《财经》· 吴俊宇 周源`）
- 存疑时以原文标注为准，**不臆造、不遗漏**
